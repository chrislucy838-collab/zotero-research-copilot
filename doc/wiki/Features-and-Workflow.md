# Features and Workflow

## Discussion

The Discussion tab is designed around the document already open in Zotero. It supports streaming responses, editable shortcuts, model selection, retry/edit flows, conversation branching, and a compact context area.

A request can combine:

- the current Zotero item or reader document;
- selected reader text;
- one or more supplemental Zotero papers;
- screenshots and image attachments;
- uploaded text, Markdown, code, PDF, or image files;
- locally stored conversation memory.

The panel keeps paper context attributed so a response can distinguish the active document from supplemental references.

## Evidence and citations

When a model returns supported paper/page citation markers, the panel parses them and associates them with the corresponding evidence context. This makes citations useful for navigation and inspection rather than treating them as plain decoration.

Citation quality still depends on the model and the available document text. The plugin cannot verify a claim that the provider did not ground in the supplied context.

## PDF and EPUB retrieval

The document layer has separate PDF and EPUB adapters. It extracts text, divides it into bounded retrieval units, and keeps source locators and section metadata. EPUB 3 navigation documents and EPUB 2 NCX structures are preferred when present; semantic headings and reading order provide fallbacks for less structured books.

Explicit section requests are routed locally when the document contains a matching publisher label. Ambiguous requests use relevant retrieval rather than sending an entire book by default.

## Multi-paper research

Use `@` in the composer to search Zotero items, or open the attachment menu and choose collection papers. Up to the panel's configured context limit can be selected. Each paper is shown as an attributed context chip and can be removed independently.

This is useful for:

- comparing methods;
- tracing how a concept changes across papers;
- checking whether two papers make compatible claims;
- building a reading sequence from a collection.

## Discover and import

Discover searches OpenAlex, Semantic Scholar, and Crossref in parallel. Results are normalized and merged by DOI, title, and other identifiers. Before import, the UI marks records already present in the active Zotero library.

The import flow lets you:

1. inspect title, authors, year, venue, DOI, abstract, and PDF status;
2. select only the records you want;
3. choose My Library or an existing/new collection;
4. cancel a long import while keeping items already created.

Metadata and PDF availability come from public indexes. No result is guaranteed to have a downloadable full text.

## Files, screenshots, and multimodal models

The composer can accept files by upload, drag and drop, and clipboard paste. The reader screenshot tool captures a selected region for discussion. The selected model must support the relevant input type; an ordinary text-only model cannot interpret an image just because it was attached.

Images generated by a compatible provider can be rendered in responses. Generation availability depends on the provider, model, endpoint, and account permissions.

## Selection translation

Selection translation shares the panel's provider/model choices. It can run automatically after a selection or wait for a button in the popup. Source language can be auto-detected, and the target language is configurable.

For PDF documents, the first use can create a local compact overview and terminology cache. For EPUB documents, the selection is used as an anchor for bounded book context. The translation popup can expose copy and add-to-note actions according to Settings.

## Persistence and notes

Chat history is stored in Zotero's local database and scoped by library and conversation context. Users can create, rename, pin, branch, edit, retry, export, and delete conversations. Responses and complete chat histories can be converted to native Zotero notes.

The memory store is local, deduplicates similar entries, ranks relevant memories, and filters prompt-injection-like content before storage. It is a convenience layer, not a substitute for a research notebook or source verification.
